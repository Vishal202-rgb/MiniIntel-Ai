1. ARCHITECTURAL & PROTOCOL CONVENTIONS
====================================================================================================

1.1 Response Payload Standard Envelope
--------------------------------------
All REST v1 endpoints return a consistent JSON envelope schema:

Success Response:
{
  "success": true,
  "data": { ... } | [ ... ],
  "message": "Descriptive success message",
  "meta": {                          // Included when paginated
    "total": 120,
    "page": 1,
    "limit": 50,
    "pages": 3
  }
}

Error Response:
{
  "success": false,
  "message": "Human-readable error description",
  "error": "SPECIFIC_ERROR_CODE_OR_MESSAGE"
}

1.2 Authentication & Token Transport
------------------------------------
- Format: JSON Web Token (JWT) signed with HMAC SHA-256 (30-day lifetime).
- Transport Header:
    Authorization: Bearer <jwt_token>
- Token Payload: { id: "<mongodb_user_object_id>", iat: <timestamp>, exp: <timestamp> }
- Middleware: server/middleware/auth.js (`authenticate` / `protect`) and
  server/middleware/authMiddleware.js (`protect`).

1.3 Role-Based Access Control (RBAC) Matrix
-------------------------------------------
The platform enforces a 3-tier role hierarchy:
1. Public: No token required.
2. Authenticated User ('user'): Basic user privileges. Scoped to own documents,
   own reports, own audit logs, and own conversational history.
3. Reviewer ('reviewer'): Technical and regulatory reviewers. Can inspect,
   comment on, and reject documents/reports. Has access to pending review queues.
4. Administrator ('admin'): Full governance access. Can view all tenant records,
   manage users, change roles, approve reports, delete records, and export system audit trails.
   CRITICAL RBAC ISOLATION: Only the identity matching process.env.ADMIN_USERNAME
   (default: "admin") can hold the 'admin' role. All role elevation attempts by
   other users are dynamically overridden and forbidden.

1.4 Standard HTTP Status Codes
------------------------------
- 200 OK: Successful query, fetch, or synchronous update.
- 201 Created: Successful entity creation (upload, register, generate).
- 307 Temporary Redirect: Redirect from legacy aliases to current canonical route.
- 400 Bad Request: Missing required parameters, failed schema validation, or malformed input.
- 401 Unauthorized: Missing, invalid, or expired Bearer token; invalid credentials.
- 403 Forbidden: Insufficient role permissions or unauthorized attempt to access another user's resource.
- 404 Not Found: Requested document, report, record, or entity does not exist.
- 409 Conflict: Duplicate upload detected via SHA-256 checksum, or concurrent duplicate task.
- 500 Internal Server Error: Unhandled backend exceptions or database failures.
- 503 Service Unavailable: Database disconnected or degraded service health.
